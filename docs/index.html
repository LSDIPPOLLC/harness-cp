Framework

What is harness engineering?

Harness engineering is the practice of deliberately configuring AI coding assistants around 7 pillars — turning a stateless tool into a context-aware, safety-bounded, continuously improving collaborator.

Without a harness, every session starts blind. The model doesn't know your build commands, coding conventions, architecture patterns, or team decisions. A good harness eliminates the first 5 minutes of every session and prevents the last 5 minutes of cleanup.

  • check_circle Context is loaded automatically, not re-explained each time
  • check_circle Quality gates catch mistakes before they reach your codebase
  • check_circle Skills decompose complex workflows into composable actions
  • check_circle Memory persists learnings across sessions

Persistence

The Memory Gap

VS Code Copilot has no built-in memory system. HarnessCP solves this with a convention-enforced architecture.

folder_open

Storage

.github/memory/ directory with typed files and a MEMORY.md index

input

Injection

SessionStart hook auto-injects relevant memories into every new session

output

Capture

Stop hook prompts the model to save new learnings before ending a session

smart_toy

Curator Agent

Dedicated memory-curator agent restricted to memory file operations

info

Convention-enforced, not platform-enforced. This system works when the model follows instructions consistently — which Claude does well. Memory is the discipline test for Copilot harness engineering.

Per-Pillar Scale

Each of the 7 pillars receives a score from 0 to 3:

0 = Absent · 1 = Basic · 2 = Solid · 3 = Excellent

Continuous Improvement

Use /harnesscp-loop to iteratively improve. It audits your harness, identifies the weakest pillar, improves it, validates the change, and repeats.

Actionable Output

The audit produces a per-pillar breakdown with specific recommendations, not just a number. Every gap comes with a concrete fix.

Getting Started

Quick Start

Get from zero to a scored harness in under 5 minutes.

1

Open your project in VS Code

Make sure GitHub Copilot is installed and Anthropic Claude is selected as the model provider.

2

Copy the skills directory

Copy the .github/skills/ directory from HarnessCP into your project.

3

Bootstrap your harness

In Copilot Chat, type the init command to generate your full harness scaffold.

/harnesscp-init
4

Audit your maturity

Run the audit to see your current score across all 7 pillars.

/harnesscp-audit
5

Iterate and improve

Use the improvement loop to continuously strengthen your weakest pillar.

/harnesscp-loop
Tradeoffs

Boundaries

Where Copilot harness engineering excels and where it hits walls.

check_circle Where it excels

  • arrow_forward Granular context via conditional instructions with glob patterns
  • arrow_forward First-class agent orchestration with tool restrictions and handoffs
  • arrow_forward Rich hook lifecycle with 8 events and JSON I/O
  • arrow_forward Cross-model routing per agent

warning Where it hits walls

  • arrow_forward Memory requires engineering (not built-in)
  • arrow_forward Permissions are distributed (harder to audit)
  • arrow_forward No built-in eval framework
  • arrow_forward Hook format differs from Claude Code (no matcher syntax)
  • arrow_forward Agent Plugin system is still preview
